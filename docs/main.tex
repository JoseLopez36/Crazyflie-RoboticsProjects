\begin{abstract}
This paper presents the implementation of a coverage path planning algorithm combined with a divide-areas strategy for multi-UAV systems. The proposed approach is validated using Crazyflie UAVs operating in an indoor environment. The system is developed within the ROS 2 framework and relies on the Loco Positioning System for accurate indoor localization. The combination of area division and coverage path planning enables efficient space exploration while reducing overlap among multiple agents. Experimental results demonstrate the feasibility of the proposed solution for coordinated multi-UAV coverage tasks with the Crazyflies UAVs.
\end{abstract}

\section{Introduction}
In recent years, the use of unmanned aerial vehicles (UAVs) has increased significantly in applications such as inspection, exploration, mapping, and search and rescue. In particular, multi-UAV systems offer clear advantages over single-agent solutions by reducing mission completion time, increasing system robustness, and improving coverage efficiency. However, coordination of multiple UAVs remains a challenging problem.

Within this context, the coverage path planning (CPP), which is a fundamental problem in mobile robotics, aims to generate trajectories that ensure complete coverage of a target area while minimizing redundancy and inefficiencies. This is done by determining a path that passes over all points in the area of interest while avoiding obstacles. When extended to multi-UAV scenarios, CPP requires additional mechanisms to distribute the workload among agents in an effective manner. This capability is essential for various applications, including search and rescue operations, precision agriculture, floor cleaning, and environmental monitoring.

This project addresses these challenges by integrating the Divide Areas Algorithm for Robotics Platforms (DARP) where the area of interest is partitioned into subregions assigned to individual UAVs. 

This practical validation of such algorithms on real robotic platforms is essential to assess their feasibility beyond simulation. Micro-UAV platforms such as the Crazyflie 2.1 \cite{Kapoutsis} provide an appropriate testbed for research in aerial robotics due to their low cost, small size, and compatibility with modern robotic frameworks. In this work, the Crazyflie platform is integrated with ROS2 \cite{macenski2022ros2}, enabling modular development and scalable multi-agent control. Furthermore, accurate indoor localization is achieved through the Loco Positioning System, which provides reliable position estimates in GPS-denied environments.

This paper presents the implementation of a coverage path planning algorithm combined with an area division strategy for multi-UAV systems experimentally evaluated in Gazebo \cite{koenig2004gazebo} for high-fidelity simulation and in an indoor environment equipped with the Loco Positioning System. The main objective is to demonstrate the feasibility of coordinated multi-UAV coverage missions using the Crazyflies and to analyze the system setup from a practical perspective, focusing on the challenges encountered during the implementation process and the solutions adopted to overcome them. This includes issues related to multi-UAV coordination, communication, localization, and integration within the ROS 2 framework, providing insights that may be valuable for future implementations on similar platforms.

The remainder of this paper is organized as follows: Section II reviews the state of the art in Crazyflies and CPP. Section III details the system implementation and architecture. Section IV presents the simulation setup and results. Finally, Section V concludes the paper and discusses future work.

\section{System Implementation}

The proposed system is developed within the ROS 2 (Robot Operating System 2) framework, leveraging its modularity and scalability for multi-robot applications. The architecture is designed to be agnostic to the underlying platform, supporting both high-fidelity simulation and real-world deployment on Crazyflie drones via the \texttt{crazyswarm2} interface.

\subsection{System Architecture}
The core logic is distributed across four custom ROS 2 nodes, each handling specific responsibilities in the coverage pipeline. The data flow and interaction between these components are described below.

\subsubsection{DARP Node}
The \texttt{darp\_node} encapsulates the Divide Areas Algorithm for Robotics Platforms (DARP) logic. It functions as a service provider, exposing the \texttt{darp\_service}. Upon receiving a mission request containing the operational area dimensions, obstacle positions, and initial robot positions, the node performs the following operations:
\begin{itemize}
    \item Discretization: Converts continuous world coordinates into a discrete grid based on a configurable cell size.
    \item Area Partitioning: Executes the DARP algorithm to divide the grid into equal, connected, and non-overlapping zones for each agent.
    \item Path Generation: Computes a coverage path for each partition using a spanning tree algorithm.
\end{itemize}
The node returns the calculated trajectories (lists of waypoints) and a zone map, which encodes the area assignment for visualization, as illustrated in Fig. \ref{fig:darp}.

\caption{DARP algorithm partitioning and trajectory generation in \textit{RViZ}.}

\subsubsection{Planning Node}
The \texttt{planning\_node} acts as the central coordinator for the multi-robot team. Its primary roles include:
\begin{itemize}
    \item State Monitoring: Subscribes to the real-time position of all agents via \texttt{/agent\_id/state/position}.
    \item Mission Orchestration: Waits for all agents to initialize before requesting a plan from the \texttt{darp\_node}. Once a solution is received, it distributes specific trajectories to each agent on their respective \texttt{/planning/trajectory} topics.
    \item Dynamic Replanning: Maintains a global map of visited cells. If a replan is triggered, previously visited areas are treated as virtual obstacles in the subsequent DARP request, ensuring efficient coverage without redundancy.
\end{itemize}

\subsubsection{Control Node}
A dedicated instance of the \texttt{control\_node} runs for each UAV, managing its flight lifecycle through a finite state machine (FSM). The FSM states are:
\begin{itemize}
    \item \textbf{INIT}: Performs system checks and sends initial setpoints.
    \item \textbf{TAKEOFF}: Commands the drone to ascend to a target altitude using the \texttt{Takeoff} service.
    \item \textbf{MISSION}: Executes the received trajectory. The node implements a path-following logic that switches to the next waypoint when the drone enters a defined acceptance radius of the current target.
    \item \textbf{LANDING}: Automatically initiates a landing maneuver upon trajectory completion.
    \item \textbf{LANDED}: Disarms the motors and terminates the operation.
\end{itemize}
This node interfaces with the lower-level flight controller via standard ROS 2 topics and services provided by the backend.

\subsubsection{Visualization Node}
The \texttt{visualization\_node} is responsible for generating visual feedback in \textit{RViZ}. It subscribes to agent positions, planned trajectories, and the zone grid, publishing corresponding \texttt{MarkerArray} messages. This allows for real-time monitoring of the coverage progress, grid partitioning, and flight paths.

\subsection{Simulation Setup}
The system was developed and validated in a Docker-based environment to ensure reproducibility. The simulation relies on Gazebo paired with the \texttt{crazyswarm2} software-in-the-loop (SITL) backend. This setup accurately models the Crazyflie dynamics and allows for testing complex multi-agent scenarios before real-world deployment.

\subsection{Real-World Implementation}
The experimental validation was conducted using real hardware to assess the system's performance in a physical environment. The setup consists of the following components:

\subsubsection{Robotic Platform}
The experiments utilize Crazyflie 2.1 nano-quadcopters. Each drone is equipped with:
\begin{itemize}
    \item Loco Positioning Deck: configured in TDoA2 (Time Difference of Arrival 2) mode. TDoA2 is selected over TWR (Two-Way Ranging) as it supports an unlimited number of listeners, making it scalable for multi-robot fleets.
    \item Flow Deck v2: provides optical flow and a ToF (Time-of-Flight) distance sensor. While the Loco Positioning System provides 3D coordinates, the vertical (Z-axis) estimation can be noisy. The Flow Deck is used to fuse stable height measurements, ensuring consistent altitude hold during the mission.
\end{itemize}
Communication between the ground station and the swarm is handled by a Crazyradio 2.0 USB dongle.

\subsubsection{Localization System}
An indoor localization infrastructure, the Loco Positioning System (LPS), was deployed using 8 Loco Positioning Nodes. To maximize the positioning volume and stability, the anchors were arranged in a cubic configuration encompassing the flight area. The nodes were placed at the following coordinates to create a diversified geometry:
\begin{itemize}
    \item Bottom Plane ($z \approx 0.75m$): Anchors at corners $(0,0)$, $(3.6, 0.0)$, $(0, 3.6)$, and $(3.6, 3.6)$.
    \item Top Plane ($z \approx 2.25m$): Anchors vertically offset from the bottom plane to ensure good geometric distribution.
\end{itemize}
This setup, shown in Fig. \ref{fig:lps}, provides accurate position estimates required for the precise grid-based navigation demanded by the DARP algorithm.

\begin{itemize}
    \item A defined workspace (e.g., $10 \times 10$ meters).
    \item Multiple Crazyflie 2.1 models.
    \item Static obstacles placed within the area.

The specific outcomes include: 
\begin{itemize}
    \item \textbf{Area Partitioning}: The algorithm successfully divided the available free space into distinct regions for each drone.
    \item \textbf{Coverage}: The generated paths covered all accessible cells within the assigned zones.
    \item \textbf{Execution}: The \texttt{control\_node} successfully guided the drones through the generated waypoints with stable flight behavior.
    \item \textbf{Replanning}: The system showed the capability to update plans dynamically by marking visited cells, although the primary focus was on static offline planning.
\end{itemize}

Visualizations in \textit{RViZ} confirmed the alignment of the planned grid zones with the real-world positions of the drones.

\section{Conclusion}
This paper presented a ROS2-based framework for multi-robot coverage path planning using Crazyflie drones. By integrating the DARP algorithm, we achieved an efficient division of labor among multiple agents. The modular architecture allows for easy extension, such as adding dynamic obstacle avoidance or scaling to a larger swarm. Future work will focus on deploying this system on physical Crazyflie hardware and implementing real-time decentralized coordination.
